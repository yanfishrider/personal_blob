## 起因

这个博客需要一个开场动画。不是那种千篇一律的 loading spinner，而是有辨识度、能和博客主题产生关联的东西。

最初冒出这个念头，是因为游戏中那些精心设计的加载画面——黑底、网格、逐行滚动的终端日志——跟网页加载的等待时间天然契合。既然都是在等，为什么不让等待本身变成一种体验？

于是我开始在网上搜"游戏风格网页加载动画"，结果令人失望：几乎找不到现成的实现。唯一沾边的是一个 P3RE（Persona 3 Reload）风格的页面加载动画，但它本质上只是两段短视频循环播放，配上几条波浪线，实现思路过于简单，效果也差强人意。

既然没有现成的，那就自己造。

我回到 NieR:Automata 里截了几张加载界面的图作为参考，然后开始拆解。第一个要解决的问题是背景中的矩阵方块像素效果——怎么在网页上还原那种密密麻麻的暗色网格？最初的直觉是用加粗的边框线条叠在深色背景上，试了几版后发现用 CSS 的 `linear-gradient` 画网格线，比 border 方案简洁得多，性能也更好。

有了网格背景打底，剩下的就是徽章渲染和终端文字——这两个问题后面分别用 Canvas 点阵映射和 JS 逐字打印解决了。

## 徽章素材：从截图到 ASCII

网格背景只是气氛组，真正的主角是正中央的 YoRHa 徽章和下方的「For the Glory of Mankind」标语。

最初的思路很直接：仿照像素字的做法，人工把徽章转成 0/1 矩阵。但打开游戏截图一看就傻眼了——截图里的徽章对比度太低，边缘模糊，靠肉眼逐行数格子根本无从下手。手工编码一个 400×70 的矩阵，光是想想就头皮发麻。

于是转头问 DeepSeek 有没有更聪明的办法，它推荐了 [asciiart.eu 的图片转 ASCII 工具](https://www.asciiart.eu/image-to-ascii)。思路一下清晰了：

1. 用豆包生成一张干净的 NieR 徽章 + 标语的图片
2. 在 Photoshop 里去水印、调对比度，让图案轮廓尽可能锐利
3. 丢进 ASCII 转换工具，导出 `ascii-art.txt`
4. 文件放到项目根目录，Astro 通过 `?raw` import 构建时加载

整个过程比手工编码快了不止一个数量级。生成的 txt 文件约 400 列 × 70 行，用 `@` 字符勾勒徽章轮廓，空格留白——这个密度方向后面踩了个坑，但那是后话了。

## 三层结构

整个动画由三层叠加构成，从底到顶：

### 第一层：CSS 网格背景

```css
background: #1C1814;
background-image:
  linear-gradient(rgba(0,0,0,0.15) 1px, transparent 1px),
  linear-gradient(90deg, rgba(0,0,0,0.15) 1px, transparent 1px);
background-size: 5px 5px;
```

深灰棕底色上覆盖 5px 间距的黑色网格线。纯 CSS 实现，零 JS 开销。每个格子就是后面点阵的基本单位。

### 第二层：Canvas 点阵徽章

这是最核心的部分。思路是把一个 ASCII art 文件逐字符映射为 Canvas 上的点阵：

1. 准备一个 400 列 × 70 行的 ASCII 文本文件（`ascii-art.txt`），用 `@` 等字符绘制 YoRHa 徽章
2. 通过 Astro 的 `?raw` import 在构建时加载文件内容
3. 建立字符→密度的映射表：

```
'@' → 0.50（最亮，绘制徽章轮廓）
'#' → 0.44
'%' → 0.38
'*' → 0.32
'=' → 0.26
'+' → 0.20
'-' → 0.14
':' → 0.08
'.' → 0.04
' ' → 0   （背景空白，透出底层网格）
```

4. 遍历每个字符，按密度值计算 alpha，用 `fillRect` 在 Canvas 上画出对应位置的点

关键参数：

```js
CELL = 1.5    // 格子大小
DOT  = 2      // 点大小（略大于格子，产生"光晕溢出"效果）
STRETCH_X = 1.5
STRETCH_Y = 2.75  // 垂直拉伸，修正 ASCII 字符的宽高比
```

这里有一个重要的设计选择：**DOT > CELL**。让点略大于格子在视觉上产生光晕溢出的效果，比严格对齐的像素感更有温度。

### 第三层：终端打字文本

HTML + JS 实现的逐字打印效果，模拟终端启动日志：

```
连接服务器 - 完成
页面资源 - 完毕
渲染引擎 - 初始化
全局样式表 - 已解析
字体文件 - 已加载
脚本模块 - 已编译
WebSocket连接 - 已建立
路由表 - 初始化
资源完整性 - 已验证
页面准备就绪
```

每行文字的渲染过程：
1. 逐字符出现，每个字符从半透明渐变为白色
2. 随机概率插入一个乱码字符（来自特殊符号字符集），短暂闪烁后替换回正确字符
3. 模拟"系统正在解码/初始化"的仪式感

## 性能考虑

- Canvas 绘制只在页面加载时执行一次，之后 `display:none` 移除 DOM
- `sessionStorage` 缓存标记，同一会话内不重复播放
- 没有 requestAnimationFrame 循环（弹幕已在早期迭代中移除）

## 迭代过程中的教训

几个踩过的坑：

1. **密度映射方向**：ASCII 文件中 `@` 的含义取决于具体文件。有些文件用 `@` 作背景。必须实际读取文件确认映射方向，否则徽章完全不可见。

2. **Canvas 透明 vs 填充**：Canvas 叠在 CSS 网格上时，`fillRect('#000')` 会盖住网格。必须用 `clearRect()` 让 Canvas 透明，底层 CSS 网格才能透出来。

3. **移除弹幕时的残留**：删除弹幕 Canvas 时必须同时删除 `cancelAnimationFrame(rainId)` 调用，否则 `rainId` 未定义导致动画永远不结束。

4. **`?raw` 路径**：从 `src/components/LoadingScreen.astro` 导入项目根目录文件，需要 `../../ascii-art.txt?raw`（两个 `../`）。

## 小结

这个动画本质上是一个「ASCII→Canvas 渲染器」+「终端模拟器」的组合。核心代码不到 100 行 JS，但效果比纯 CSS 动画有辨识度得多。

如果你也想在自己的项目里用类似的效果，把 `ascii-art.txt` 替换成你自己的 ASCII 图案就行，参数调一下 `STRETCH_X/Y` 就能适配任何尺寸。
