## 缘起

动画实验室新加一项：卡片中间有一条拉链，左右两片幕布从中间咬合，把内容遮住；拖动拉链头往下拉，幕布随开口退向两侧，内容露出来，拉到底时幕布整片移出卡片。可逆。

需求定得很具体，一共五条：

1. 是一块**卡片区域**，不是整屏遮罩
2. 按钮能触发，鼠标也能**直接拖拉链头**，可逆
3. 拉开到一定宽度后**等宽往下走**（不是一直越拉越宽的 V）
4. **左右两排链齿**
5. 内容**从里往外推**出来

第一版做出来能开能合，但有两个问题：鼠标**完全拖不动**，而且幕布只是"开口变宽"，没有"两片布被推开"的感觉。后面两轮迭代基本都在修这两件事。

## 先拆元素，再谈动画

一共四个元素层，从上到下：

| 层 | 内容 | 关键点 |
|---|---|---|
| 内容层 | 卡片里的标题/说明/标签 | 被幕布遮住，用 `--p` 驱动 scale + 亮度 + 模糊 |
| 幕布 | 左右两片，内边缘是折线 | 形状每帧重算，只有 4~6 个点 |
| 链齿 | 左右两排 | 右排错开半格才是"咬合" |
| 拉链头 | 滑块 + 拉片 | 位置 = 开口底端 + 偏移量 |

四个里，**链齿的咬合是可信度的分水岭**。两排齿如果只是平行排列、齿尖对齿尖，看起来像两条拉链放在一起，不像一条拉链。真实拉链的左右齿是互相插进对方缝隙里的，所以右排整体下移半个齿距，闭合时左齿占 `[CX−4.4, CX]`、右齿占 `[CX, CX+4.4]`，正好在中缝相接。

## 开口的几何模型

### 第一版：一个 clamp 就够了

开口半宽只需要一个分段线性函数——距离"开口底端"越远越宽，超过过渡带就恒定：

```js
// WM = 最大半开口，L = 过渡带长度
function xEdge(y, open) {
  var d = open - y;                 // 该点距离开口底端多远
  if (d <= 0) return 0;             // 拉链头以下：仍咬合在中缝
  return d >= L ? WM : WM * d / L;  // 过渡段线性张到 WM，再往上等宽
}
```

这三行同时满足了需求 3：`d >= L` 之后恒为 `WM`，视觉上就是"张开到一定宽度后等宽往下走"。`L` 是唯一的手感旋钮——越小，"V" 越尖。

| y 区间 | 语义 | 内边缘位置 |
|---|---|---|
| `y > open` | 拉链还没拉到，两片咬合 | `CX`（中缝） |
| `open − L < y < open` | 过渡段，斜着张开 | `CX ± WM·(open−y)/L` |
| `y < open − L` | 等宽段 | `CX ± WM` |

### 撞上的第一个坑：闭合状态顶部漏一条缝

写完一算极端值就发现不对：`p = 0`（完全闭合）时，顶部居然有 41 单位宽的开口。

根因是**把"拉链头位置"直接当成了"开口底端"**。拉链头中心不能贴着卡片顶边——拉片挂在滑块上方，得给它留出空间（`HANDLE_PAD = 42`），于是拉链头中心在 y=52。而开口是按"离拉链头的距离"算的，`xEdge(0) = 118 × 52/150 = 40.9`——顶部凭空多了一段开口。

修法是把两个概念拆开：

```js
var open = pc * OPEN_MAX;          // 已拉开长度：从卡片顶边往下量，= 开口底端 y
var ys   = open + HANDLE_PAD;      // 拉链头（把手）中心 y
```

`xEdge` 只认 `open`，把手位置独立算。这样 `p = 0` 时 `open = 0`，全场 `xEdge = 0`，真闭合；而把手仍然停在 y=42，拉片顶端正好贴卡片顶边。**同一件事（拉链头在开口底端）在视觉上要靠两个变量表达，混成一个就会在极端状态下露馅。**

### 第二版：不是"变宽"，是"被推开"

第一版的幕布永远留在卡片里——最大开口 `WM = 118`，两片布各留 118 宽的边条贴在两侧。用户要的是"幕布向两边散开，拉到底彻底移出容器"。

于是把两个常量改成随进度变化的函数：

```js
var A = WM + SPREAD * Math.pow(pc, 1.2);   // 最大半开口：118 → 380
var T = L  * (1 - 0.84 * pc);              // 过渡带：150 → 24（越拉越陡）
```

`A(1) = 380 > CX = 310`——这是关键：只要最大半开口超过容器的半宽，内边缘就会跑到容器外面去。再把幕布的外边界也跟着外移（`−A` / `W+A`），整片布就被"推出"了容器。

`T` 越来越小则负责"散开感"：斜边越拉越陡，两片布越来越像是被甩开，而不是缓缓张开。

实测三个阶段（数值来自 node 验证脚本的真实输出）：

| p | A / T | 左幕布 `d` | 拉链头 y |
|---|---|---|---|
| 0 | 118 / 150 | `M-118 0 L310 0 L192 0 L310 0 L310 400 L-118 400 Z` | 30（拉片贴顶边）|
| 0.5 | 232 / 87 | `M-232.04 0 L77.96 0 L77.96 113 L310 200 L310 400 L-232.04 400 Z` | 230 |
| 1 | 380 / 24 | `M-380 0 L-70 0 L-70 376 L310 400 L310 400 L-380 400 Z` | 430（滑出底边）|

`p = 0.5` 时两片布各只剩 78 宽在卡片内（开口 464），左边界已经被推到 −232；`p = 1` 时内边缘 −70、外边界 −380，**卡片内已经没有幕布**，内容完全显示。

有一个几何上的必然要提前说明：拉链头所在的位置两片布**必须**咬合（否则拉链头就成了一个断开的零件），所以 `p = 1` 时卡片底部两角会各留一块三角形残布，高 = `T(1) = 24`（约卡片高的 6%）。内容居中不受影响；真嫌碍眼就把陡峭度系数从 0.84 调到 0.95，残角只剩 7 单位。

## 链齿：41 个实例，每帧只改一个属性

齿的定义放 `<defs>` 里做成一个可复用元件（齿身 + 一道高光），实例化时只写 `x` / `y`：

```js
for (i = 0; i < 41; i++) {
  y = 8 + i * PT;                                  // 左排
  var ul = document.createElementNS(SVGNS, 'use');
  ul.setAttribute('href', '#zTooth');
  ul.setAttribute('y', y);
  gL.appendChild(ul);

  var yr = 8 + PT / 2 + i * PT;                    // 右排错开半格 → 咬合
  var ur = document.createElementNS(SVGNS, 'use');
  ur.setAttribute('href', '#zTooth');
  ur.setAttribute('y', yr);
  gR.appendChild(ur);
}
```

每帧渲染时，齿的 x 直接由幕布内边缘决定，于是"齿跟着布走、越往上越散"是自动的：

```js
teethL[k].el.setAttribute('x', fmt(CX - xEdge(teethL[k].y) - 2.2));
teethR[k].el.setAttribute('x', fmt(CX + xEdge(teethR[k].y) + 2.2));
```

几个取舍：

- 用 `<use>` 一个元件 + 每帧改 `x` 属性，而不是给 82 个齿写 82 段 `transform` 字符串——属性写入比字符串解析便宜，实测拖动全程无掉帧。
- 齿中心落在 `边缘 ∓ 2.2`（骑在边缘**内侧**），不是外侧。第一版我按"齿在边缘外面"写，闭合时左右齿之间会空出一条 0.6 的缝，怎么调都像没咬上。
- 齿数由容器高度决定（`41 = 400 / 9.5`），换尺寸时只改 `PT`。

## 按反馈做的简化

第一版做得偏"仿真"：两套金属柱面渐变、滑块中间的深色竖槽、底部 Y 形汇合线。反馈是**"小一点、没必要太仿真、颜色改成 #7DB6BF"**，于是：

| 项目 | 旧 | 新 |
|---|---|---|
| 链齿尺寸 | 6.4 × 6.2 | 4.4 × 4.4 |
| 齿距 / 齿数 | 12.5 / 31 | 9.5 / 41 |
| 拉链头 | 34 × 46 | 22 × 29（约 2/3）|
| 配色 | 两套金属横向渐变 | 单色 `#7DB6BF` + 描边 `#4a7f88` + 一道高光 |
| 装饰 | 竖槽 + Y 形汇合线 + 强投影 | 全删，投影调轻（dy 3 → 2）|

去掉渐变之后反而更像"元件"而不是"渲染图"，也更贴合动画馆整体的青色系。

## 交互：拖动要跟手，按钮才有动画

两种输入方式是两种性格，不能共用一条路径：

- **拖动**：`pointerdown` 记录起点，`pointermove` 里按像素位移直接换算 `p`，**不加任何缓动**——慢半拍就不像在拖东西了。用 Pointer Events + `setPointerCapture`，鼠标和触摸同一套代码。
- **按钮**：走 rAF tween，配 `easeOutBack` 轻微超调，拉到底有"咔"一下的机械感。时长按距离算（`max(380, |Δp| × 820)`）。
- **拉片摆动**：角度由拖动速度驱动（`clamp(−v × 1.6, ±26)`），松手后按 0.86 衰减回正。细节很小，但它让拉链头"有重量"。
- **端点吸附**：松手时 `p > 0.96` 自动补到 1、`p < 0.04` 回到 0，中间位置保持不动（用户要可逆，不能自作主张吸附）。

## 关键坑：`querySelector('rect')` 把事件绑到了装饰元素上

用户报的第一句话是"**不能用鼠标拉动**"。按钮正常，拖动全无反应。

抓取区（一块 44×76 的透明热区）写在滑块 `<g>` 的**最后**——也就是最上层，命中测试必然落在它身上。但事件是这样绑的：

```js
var hit = slider.querySelector('rect');   // ← 真凶
```

`querySelector('rect')` 返回的是**第一个** `rect`，也就是滑块中间那根 4.4px 宽的装饰竖槽。结果：点击落在透明热区上（它在最上层），监听器却挂在那根细线上——**两者永远对不上，等于完全拖不动**。

修法很轻，但规则值得记死：

```html
<rect id="zHit" x="-16" y="-30" width="32" height="54"
      fill="transparent" pointer-events="all" style="cursor:grab" />
```

```js
var hit = document.getElementById('zHit');
```

两条泛化规则：

1. **父容器 `.querySelector('tag')` 取交互元素一律不可靠**——同 tag 的装饰元素会抢先。交互元素必须给 id。
2. 透明热区必须显式写 `pointer-events="all"`：`fill="none"` 的元素不参与命中测试，视觉上"在那儿"但点不到。

## 无浏览器验证：node + DOM 桩跑真脚本

视觉改动我不起浏览器截图（自己看更快），但**逻辑必须真跑**。做法是把页面的 `<script>` 抽出来，用最小 DOM 桩执行：

```js
const code = src.match(/<script type="module">([\s\S]*?)<\/script>/)[1];
new Function('document', 'performance', 'requestAnimationFrame', 'cancelAnimationFrame',
             code)(document, performance, requestAnimationFrame, cancelAnimationFrame);
```

桩有三个必须做对的点，每一个都真的踩过：

| 坑 | 症状 | 正解 |
|---|---|---|
| `style` 是普通对象 | `content.style.setProperty is not a function` | `const style = { setProperty(k,v){ style[k]=v; } }`（自引用）|
| `performance.now()` 恒定 | tween 里 `k` 永远是 0 → 死循环 | 每次调用 +100ms，让 tween 在 ~10 帧内收敛 |
| `querySelector` 桩随便返回对象 | **掩盖上面那个"拿错元素"的 bug** | 交互元素一律走 `getElementById` + els 表 |

有了它就能直接断言行为，而不是读代码猜：

```text
=== 鼠标拖拽 → p=0.5 ===
  左幕布 d = M-232.04 0 L77.96 0 L77.96 113 L310 200 L310 400 L-232.04 400 Z
  右幕布 d = M852.04 0 L542.04 0 L542.04 113 L310 200 L310 400 L852.04 400 Z
  PASS  拉链头 y = open+HANDLE_PAD = 230
  PASS  p=0.5：82 个链齿全部符合参考公式
  PASS  松手不吸附（保持 p=0.5）

=== 点按钮 → tween 到 p=1（幕布整片移出容器）===
  PASS  p=1：顶部内边缘 = CX-380 = -70（容器内已无幕布）
  PASS  p=1：拉链头滑出容器底边 y=430
  PASS  p=1：内容层 --p = 1（内容完全显示）
  PASS  可逆：回到闭合
```

其中"82 个链齿全部符合参考公式"是脚本里**另写一份**独立的 `xEdge` 参考实现，逐齿比对——这样参数改错、循环少一个、边界漏判都会立刻报出来，比抽看两个齿的数字可靠。

## 参数表

| 变量 | 值 | 作用 | 调大的效果 |
|---|---|---|---|
| `WM` | 118 | p=0 时的最大半开口 | 初始开口更宽 |
| `SPREAD` | 262 | 散开增量（`A(1) = WM + SPREAD = 380`）| 拉到底推得更远；必须 > `CX` 才会出容器 |
| `L` | 150 | p=0 时的过渡带长度 | 斜边更长、更"软" |
| `0.84` | — | 陡峭度系数（`T(1) = L × 0.16`）| 残角更小、散开更利落 |
| `PT` | 9.5 | 齿距（齿数 = `H / PT`）| 齿更疏 |
| `OPEN_MAX` | 400 | 拉开总行程 | 到底时闭合段长度 |
| `HANDLE_PAD` | 30 | 拉链头中心低于开口底端的量 | 拉片露出更多 |

## 经验

1. **同一件事可以需要两个变量**。"拉链头在开口底端"看着是一个事实，但"开口底端在哪"和"把手画在哪"必须分开算——合并成一个变量，闭合状态立刻就漏缝。
2. **几何模型先算极端值再写代码**。`p = 0` 和 `p = 1` 各代入一遍，比在浏览器里拖来拖去快得多——这次顶部漏缝就是算出来的，不是看出来的。
3. **交互元素一律给 id**。父容器 `querySelector` 会拿到装饰元素，而这正是"按钮好使、鼠标拖不动"这类一半能用的怪现象的来源。
4. **被每帧跟踪的属性不能挂 CSS transition**（上一篇文章记录的教训）：这里内容层的推进用 `--p` 变量 + `calc()`，全程没有 transition，所以拖动时严格跟手。
5. **无浏览器验证法值得为交互单独写一次脚本**。这次的 DOM 桩不仅复现了"拖不动"，还顺带把 `p=1` 的边界条件验穿了。

## 踩坑记录

| 症状 | 根因 | 修法 |
|---|---|---|
| p=0 时顶部漏出 41 单位开口 | 开口底端与把手位置耦合 | 拆成 `open` / `handleY = open + HANDLE_PAD` |
| 按钮能用，鼠标完全拖不动 | `slider.querySelector('rect')` 拿到 4.4px 的装饰竖槽 | 热区加 id，用 `getElementById` |
| 桩跑不起来：`setProperty is not a function` | 桩的 `style` 是普通对象 | 自引用 `style` 对象 |
| tween 在桩里死循环 | `performance.now()` 恒定 → `k` 永远 0 | `now()` 每次 +100ms |
| 闭合时两排齿之间有空隙 | 以为齿在边缘外侧 | 齿骑在边缘内侧，闭合时于中缝相接 |
| 幕布只是变宽、不散开 | 最大开口是常量 `WM` | `A(p)` / `T(p)` 随进度变化 + 外边界外移 |

## 结语

第 5 项已挂在动画馆（可直接访问 `/lab-zipper/`）。真要继续做质感，下一步是"分片伪 3D"：把每片幕布竖切成 20~40 条，靠近中缝的条先动、远的滞后，用错峰位移做出布料被拖开的波浪感——纯 transform，成本不高，但这一版的"平整布"会立刻变得有厚度。
