## 需求

把数学试卷的扫描 PDF 自动解析为结构化题目，然后逐题求解、验证、输出标准答案。输入是纸质试卷的扫描件，输出是 JSON + Markdown + DOCX。

## 整体 Pipeline

```
PDF → 分页截图 → Qwen-VL 识别 → structurize 结构化 → 
逐题求解 → Critic 反向验算 → LLM 二次验证 → 汇总输出
```

### 第一步：视觉识别

Qwen-VL 负责把试卷图片转成文本。数学试卷的难点在于公式、分数、根号、几何图形——普通 OCR 完全不行，但 Qwen-VL 作为多模态模型可以直接"看懂"题目内容。

### 第二步：结构化

识别出来的是自由文本，需要解析为结构化数据。用 DeepSeek 将每道题拆分为：题号、题型、题目文本、选项（选择题）、答案区域。正则表达式作为兜底——LLM 输出不稳定的时候，代码层做二次拆分。

### 第三步：逐题求解与验证

每道题一个独立循环：

```
求解脚本 → 计算答案 → Critic 检查 → 反向验算 → LLM 验证
```

- **求解**：DeepSeek 生成 Python/数学推理，执行得到答案
- **Critic**：检查答案格式、数值范围、逻辑一致性
- **反向验算**：把答案代回原题验证（比如把根代入方程）
- **LLM 验证**：让模型自己确认答案是否合理

如果验证 FAIL，重试最多 5 次。UNCERTAIN 重试 1 次。只有 PASS 才进入下一题。

### 关键经验

**分批处理**：DeepSeek 单次调用超过 15 题会返回空，需要拆成每批 10-15 题。

**LLM 验证也要分批**：验证阶段每批超过 4 题也会返回空，最稳的方案是每批只验证 1 题。

**答案精度**：数学题的答案保留精确形式——分数不转小数（`100/3` 而非 `33.333`），π 保留符号（`377π/10` 而非 `118.38`），只有题目明确要求近似值时才例外。

## 输出

最终生成三份文件：
- `output.json` — 结构化数据（供程序消费）
- `output.md` — Markdown 格式（供人工查看）
- `output.docx` — Word 文档（供打印/分发）

## 结论

这个 Pipeline 的核心思路是"不信任 LLM 的单次输出"——每一道题都经过求解→验证→再验证的循环。准确率比直接让 LLM 生成答案高出不少，代价是处理时间和 API 调用量。对于需要高精度的场景（比如试卷批改），这个代价是值得的。
